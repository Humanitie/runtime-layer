# API Documentation — Humaniti AI Runtime Layer Backend

Base URL (local): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

All endpoints accept these headers to simulate an authenticated user (a real
deployment resolves these from SSO/JWT instead):

| Header | Example | Notes |
|---|---|---|
| `X-User-Id` | `demo-user` | Any string |
| `X-User-Role` | `CFO` | One of `CFO`, `Finance Manager`, `Project Manager`, `Delivery Lead`, `Employee`, `Admin` |
| `X-User-Name` | `Farah` | Display name, used in audit trail |

Role → domain permission matrix (enforced by the Context Engine before any model call):

| Role | finance | delivery | knowledge | hr |
|---|---|---|---|---|
| CFO | ✅ | ✅ | ✅ | ✅ |
| Finance Manager | ✅ | ❌ | ✅ | ❌ |
| Project Manager | ❌ | ✅ | ✅ | ❌ |
| Delivery Lead | ❌ | ✅ | ✅ | ✅ |
| Employee | ❌ | ❌ | ✅ | ❌ |
| Admin | ✅ | ✅ | ✅ | ✅ |

## `POST /api/delivery/analyze`

Runs delivery risk intelligence over a simulated project.

**Body**
```json
{ "project_id": "PRJ-1001", "question": "Assess overall delivery risk and recommend mitigations." }
```

**Response** — see the shared response schema below.

---

## `POST /api/finance/decide`

**Body**
```json
{ "question": "Can we approve this $500,000 vendor payment to ABC Technology Consulting?" }
```

Amounts over $250,000 are hard-classified `HIGH` risk by the deterministic
`JudgmentEngine` regardless of what the model concludes.

---

## `POST /api/knowledge/ask`

**Body**
```json
{ "question": "What is the process for onboarding a new vendor?" }
```

If no relevant document is retrieved, the model is never called — the endpoint
returns the "I do not have enough verified information" fallback directly.

---

## Shared response schema (all three endpoints above)

```json
{
  "risk_level": "LOW | MEDIUM | HIGH",
  "decision": "informational | recommended | requires_human_review",
  "confidence": 0,
  "conflict_detected": false,
  "summary": "string",
  "reasoning": "string",
  "root_causes": ["string"],
  "recommendation": "string",
  "sources": ["DOC-ID"],
  "audit_id": "AUD-00001",
  "ai_mode": "production | demo | demo-fallback | n/a",
  "reasoning_source": "Claude API | Enterprise Scenario Engine | Verification Engine (no evidence — no provider called)",
  "human_action_required": true,
  "low_confidence_escalation": false
}
```

`ai_mode` / `reasoning_source` tell you which engine actually answered — see the AI
Provider Abstraction section of `ARCHITECTURE.md`. `demo-fallback` means Claude was
attempted, failed, and the Enterprise Scenario Engine answered instead; the failure is
recorded in `GET /api/health`. `low_confidence_escalation: true` means the response was
automatically routed to human review because its confidence fell below 40%, even
though the risk classification alone wouldn't have required it.

## `POST /api/governance/decide`

Records a human decision against a pending audit record. Fails with `400` if the
record wasn't flagged `requires_human_review`, and `404` if the `audit_id` doesn't exist.

**Body**
```json
{ "audit_id": "AUD-00001", "decision": "Approved", "by": "Farah", "reason": "Confirmed with Finance Director." }
```

## `GET /api/governance/pending`

Lists all audit records awaiting a human decision.

## `GET /api/audit`

Full audit trail for the running session.

## `GET /api/dashboard`

Executive dashboard payload: health score, pending decisions, escalation count,
per-project risk, bottleneck categories, and `ai_mode` (the configured provider mode:
`production` / `demo` / `auto`).

## `GET /api/health`

Includes `ai_mode_configured` (what `AI_MODE` is set to) and `ai_mode_effective`
(`production` or `demo` — what the next request will actually use, accounting for
whether a key is present in `auto` mode) alongside `recent_errors`, each with a
`suggested_fix`, and an overall `health_score`.

System health / self-monitoring status, including recent errors with suggested fixes.
